git status 显示 README、docs/30/40/50/51/52、artifacts、role-protocol、state-machine、check-config.py 等已修改未 commit。
框架自身规则要求"每个评审门后 wip 提交（产物保护与取证）"；60-review v2 曾因空 Write 覆盖且未入 git 而不可恢复。当前最新产物处于同样风险。
B · 轻｜行号引用漂移（规范自违反 13.4）
DrawService.cs:27 注释引用"30-architecture D-08（:544）"，实际在 :567（v4 修订后漂移 +23 行）。

C · 轻｜60-review v6 证据陈述与事实不符
§H.3-c 称"src/ 未入 git（git ls-files src = 0）"；实测 190 个 src 文件被跟踪、git log 含 feat(backend/frontend) 提交。
影响：该轮本可取得"版本控制级"证据（git diff），却降级为行号位移旁证；结论正确但证据声明失实。
D · 轻｜D-06 散文句与配置文件现状张力
架构称"确定性配置只允许出现在 appsettings.Development.json"，但生产基线 appsettings.json 与 Testing.json 均含该节（Enabled=false / 空覆盖）。
功能安全（校验规则泄漏即拒启）；属文档内措辞不自洽，规范 3.x 第 1 条已记录同类教训但未回改 D-06 散文。
E · 观察｜附录 A 第 6 条"±1 转换"描述与实现形态不符
规范称 usePagination 收敛"TanStack pageIndex(0 起)↔接口(1 起)"的 ±1 转换；实际 usePagination 纯 1 起直通后端，TanStack 仅用 getCoreRowModel 渲染、未接入分页状态机。
实现更简、规范滞后（转换点实际不存在）。
