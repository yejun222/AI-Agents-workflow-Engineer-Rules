# 配置交叉核对清单（config-checklist）

> **能机械断言的检查项已移入 `tools/check-config.py`**（`python3 tools/check-config.py` 一键运行）。本清单只保留**需要人判断**的条目：改动角色 / 命令 / 文档后，先跑脚本，再按下面逐条人工过一遍。

## A. 产物登记表回溯

- [ ] `docs/artifacts.md` 的「读取者」列，是否与每个角色文件「输入要求」里读的文件**逐一对上**（含新增角色、新增产物）？
- [ ] 产物路径变更时，`/feature`、单步命令、`docs/state-machine.md` 里引用的路径是否同步更新？

## B. 编排命令回溯

- [ ] `/feature` 每一步的输入清单，是否与 `artifacts.md` 的读取者列一致？
- [ ] 每个含条件的步骤（如"若我说不用归档"）是否列出了**全部**受影响的步骤？⚠️ 只排除"后续"步骤、漏掉该步骤自身的输入，是本清单反复放过的形态。
- [ ] 每个「暂停等我决定 / 交给我决断」是否都写了**我选 A 做什么、选 B 做什么**？只有暂停没有后续动作 = 悬空分支。
- [ ] 新结论/新分支（如"带残留接受"）是否同时在发布门槛/状态机里**定义了该结论**？只有一个文件提它 = 无定义结论。
- [ ] 计数器（"最多 2 轮 / 1 轮"）是否说明：人工触发的重跑算不算进上限？
- [ ] **本次是否引入或修改了「同一事实的第二个落点」**（精简版 ↔ 全量版、规范正文 ↔ 角色提示词、契约 ↔ 用例、同一配置的多个消费点、同一编号的多份产物）？是 → **必须同步新增一条把两处逐字绑定的护栏断言**（范式：`check-config.py` 的 T14 / T16），否则必然分叉。⚠️ 本仓库实测的**六个不同领域的坑是同一个根因**（客户端/服务端超时配置、前端/后端超时预算、同一事务多个写路径的错误分类、同一配置的三处兜底、产物编号撞车、规范正文引用未登记的号码）——不要因为"这次只是文字"而跳过

## C. 状态机与结论一致性（脚本已查字符串，人工查语义）

- [ ] `docs/state-machine.md` 每个结论分支，在 `/feature` 与测试角色里的**执行动作**是否自洽（谁能触发、谁落盘、谁签署）？
- [ ] 测试角色的「建议结论」范围是否**明确排除了**只有主对话能授权的结论（有条件发布（含残留缺陷））？
- [ ] 修复循环出口已定义：第 2 轮后只要存在未消除阻断项（不限致命 / 严重）就交用户决断（state-machine 修复循环 c「出口与缺陷级别解耦」）；修复分派按触发原因（缺陷 → engineer，覆盖 / 用例缺口 → 测试角色）。

## D. 交付前核查

- [ ] 角色文件：frontmatter 完整（`name` / `description` 双引号 / `tools` / `model` / `maxTurns` / `color`），description 含"不负责 → 其他角色"互斥指向。
- [ ] 写入范围：每个角色「可写 / 只读」与 `artifacts.md` 速查表一致；`Bash` 用途已限定（构建 / 测试 / 验证）。
- [ ] 已跑 `python3 tools/check-config.py`，全部断言通过。
- [ ] 本次新增 / 修改 `tools/check-config.py` 断言后，已运行 **`python tools/check-config.py --self-test`** 并全部通过？该命令把本项要求自动化：逐条突变 → 断言目标断言 FAIL → 还原 → 断言恢复全 PASS。⚠️ **每例必须先断言「变更确实发生」**——不先断言，`replace` 未匹配会静默不动，于是「没验证」被当成「验证通过」，把假阴性写进护栏。新增断言后**必须把对应突变追加进 `MUTATIONS`**，否则新断言永远没被负向验证过。
- [ ] 护栏自测本身也有辨别力：突变**必须破坏锚句在该文件中的全部落点**（用 `replace` 全量替换，不要 `count=1`）。实测教训：两条锚句在同一文件中各有 2 个落点，只改第一处时锚句仍在，自测报「未捕获」——那是**突变太弱**，不是护栏瞎了，别据此去删断言。
- [ ] 反向核对：把「暂停」点全部列出来（`/feature` 第 0/5/7 步 + 各角色待确认清单 / 契约冲突上报），逐个确认有后续动作。
- [ ] 结论字符串比对：`state-machine.md` ↔ `test-executor` 逐字一致，test-executor 不得自造状态机未定义的结论；`/feature` 只允许引用状态机（形式：按 `docs/state-machine.md` 判定），**不得出现裸结论字符串**；每个结论分支必须可达（有一个分支永远走不到，就是死分支）。
- [ ] `60-review` 的 REV 编号与状态（`未闭环` / `已闭环` / `已接受（用户决断）`）已在 `docs/artifacts.md` ID 体系登记；`已接受（用户决断）` 仅在主对话转达后由 code-reviewer 落盘。
- [ ] 无同名 agent 文件（同名只加载一个，且 `/doctor` 会报警）；新角色已进 `README.md` 角色清单与交接链图。
- [ ] **OBS 等「按产物命名空间限定」的编号**：跨产物引用是否带文件名前缀（`51:OBS-nn`）？是否存在编号撞车（同一编号在两份产物中指向不同内容）或序列断号？`error-codes.md` 的号码是否都在注册表登记、且规范正文引用的每个号码都能在注册表查到（T15 已机器断言）？
- [ ] **本轮所有「未审 / 未执行」项**是否都登记为 OBS，且**含责任人 + 计划执行时点**？（只声明"如实未审"= 该项永远不会被处理，实测有项跨 4 个版本挂着）
- [ ] **双落点锚句**（T16 的 6 条）在改动规范条款后是否仍然逐字一致？改动任一处的措辞都会使断言 FAIL —— 这是**预期行为**，同步改另一处即可，**不要删断言**
- [ ] `role-protocol.md` §5（启动 / 就绪）与 `tests/e2e/**` 实际代码是否一致：启动 helper **唯一**、`cwd` 锁死发布目录、就绪判据走**依赖配置最深**的那条路径（`/health`、匿名接口、`401` 类判据都是**伪就绪检查**）。⚠️ 实测出现过**规则已改而门禁判据未改**的情形（规则写「必须签发令牌」，脚本的就绪门禁仍是 `GET /prizes → 401`，签发调用排在门禁**之后**）——两者不一致时以**脚本实际行为**为准排查，不得拿规则文本当作已生效的证据。
- [ ] **E2E 工具链自身是否就绪**（§5 第 4 条）：浏览器内核已装（`node node_modules/@playwright/test/cli.js install chromium`，**不在 `npm ci` 范围内**）；**前端用浏览器实测过「应用已挂载」**（等 `page-*--default` 锚点出现），而不是只看 `GET /` 返回 200。⚠️ 实测这两个缺口都会让**几十条用例同时失败**且表象像产品崩了（前者 1ms 瞬时失败，后者 30s 超时），而常规 HTTP 探测**全部返回"正常"**。

## E. 已知优化（未启用，改动前先读这里）

- [ ] **环境约束单点登记（触发条件已大幅超出，待裁决）**：跨产物反复复述的环境约束，**当前已有 7 条**——① 路径含特殊字符 → `npm run *` 不可用（命令表）；② 控制台 GBK（`role-protocol` §6）；③ shell 环境变量赋值不能加引号（§6）；④ 临时验证目录不可删、改用唯一前缀目录（§6）；⑤ 长驻进程锁死构建输出目录 → 一律写临时 `OutputPath`（§6）；⑥ **路径含 `#` → Vitest/Vite 自身解析失败**（命令表；与 ① 是**两个独立事实**：① 是 npm 经 `cmd.exe` 的展开问题，⑥ 与 npm 无关，直调 node 入口同样失败——实测它不仅废掉前端单测，还让 **Vite dev server 起不来**，进而使全部浏览器 E2E 用例以"产品缺陷"的表象失败）；⑦ **`env VAR=value cmd` 可能被 PATH 上的同名脚本劫持**（§6，实测为 uv 的 PATH 片段：只改 PATH、不执行传入命令、退出 0）。**已远超本项原定触发线（4–5 条）**，且 ⑤ 与命令表、① 与 ⑥ 均存在处置交叉。**升级为单点登记需新增 `env-constraints` 文件并同步 `artifacts.md` ID 体系、`check-config.py` 三向对齐与本节 —— 属「新增文件 + 改动框架结构」，按 `CLAUDE.md`「四、必须确认的场景」须先征得同意，故仅登记触发事实、不擅自升级。**
  **另**：「同一约束在不同产物里给出**互相矛盾**的处置」这一触发条件也已出现一次 —— `playwright.config.ts` 把「路径含 `&`」写成**本机事实**，而该断言已随仓库改名失效（规范侧写的是条件式「含 `&`（或空格）时」，仍然成立）。**已签署产物中的历史复述不回改**（属"当时如实记录"，回改会破坏取证价值），但**配置文件与代码注释里的实然陈述必须随事实同步**。
