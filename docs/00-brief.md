### CR-01 —— 密码强度规则收紧（A1 契约冲突裁决）

| 项 | 内容 |
| --- | --- |
| 提出人 | 用户（在第 3 步 `/arch` 评审门裁决 software-architect 上报的 A1） |
| 时间 | 2026-09-17 |
| 类型 | 需求收紧（非功能性安全要求提升） |

**冲突描述**：`docs/10-prd.md` FR-01-2 规定密码「8–20 位，至少同时包含字母与数字」；`docs/development-spec.md` 8.1 规定「长度 ≥ 8，含大小写字母 + 数字」。二者在**字符类别**维度冲突。

**裁决（用户原话）**：「关于A1，按照development-spec 8.1 要求『含大小写字母 + 数字』，涉及其他成果一并修改。其他冲突采用架构师默认假设」

**裁决结果**：按规范 8.1 口径收紧 —— 密码须**同时包含大写字母、小写字母与数字**。

**裁决边界（最小改动，以下三项不在本次变更内）**：

1. **长度保持「8–20 位」不变**。规范 8.1 的长度要求为「≥ 8」，与 8–20 不冲突（8–20 ⊂ ≥8），故沿用 PRD 现口径；上限 20 亦符合 BCrypt 的输入长度实践。
2. 规范 8.1「首次登录强制改密」原文标注为「可选开启」，本期**不启用**，不引入该流程。
3. 本次仅变更**字符类别**一项，其余注册/登录规则（用户名 4–20 位不区分大小写唯一、两次输入一致、BCrypt 存储、登录失败统一文案）均不变。
