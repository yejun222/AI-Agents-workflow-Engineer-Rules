# 缺陷闭环状态机（权威判定表）

`feature.md` 第 7 步与 `test-executor` 的「建议结论」都引用本表。**结论字符串只在本文件定义一次**，任何分支引用的字符串必须与本表逐字一致（多一个字、少一个括号都会让字面匹配落空）。

## 输入事实

- **F1**：`docs/51-defects.md` 是否存在 `状态=未闭环` 的**致命 / 严重**缺陷？
- **F2**：`docs/52-qa-report.md` 的**事实部分**（缺陷分布、覆盖情况、证据路径）
- **F3**：主对话是否已在调度指令中**转达**「用户已接受」决定（含接受人、理由、补丁计划）？
- **F4**：主对话是否已明确指示「**带残留接受**」？

## 判定顺序（从上到下，首个命中即结论）

| # | 事实条件 | 结论 | 主对话动作 |
| --- | --- | --- | --- |
| 0 | **F1 = 是** 且 **F4 = 否**（安全网：无论 F2 结论为何；F4 判断依据 = 主对话是否已明确指示「带残留接受」） | **不可发布** | 进入修复循环（防"质评结论与缺陷台账不一致"） |
| 1 | 无未闭环致命 / 严重；覆盖达标、无一般缺陷 | **可发布** | 进入交付 |
| 2 | 无未闭环致命 / 严重；存在一般缺陷且 **F3 = 已转达接受** | **有条件发布** | 重新调度 test-executor（输入 51/52 原文 + 转达接受决定），把 52 落为「有条件发布」（接受人 / 理由 / 补丁计划），对应缺陷状态改为 `已接受`；交付。**不进修复循环** |
| 3 | 无未闭环致命 / 严重；存在一般缺陷且 **F3 = 未转达** | **不可发布（待确认接受）** | 暂停，把一般缺陷清单交用户：选择「接受」→ 按行 2 执行；「返工」→ 进入修复循环。**两种情况都不要自行进入修复循环** |
| 4 | 无未闭环致命 / 严重；但覆盖不达标或存在其他阻断项 | **不可发布** | 进入修复循环 |
| 5 | **F1 = 是** 且 **F4 = 已指示「带残留接受」** | **有条件发布（含残留缺陷）** | 重新调度 test-executor，把 52 落为「有条件发布（含残留缺陷）」（缺陷编号 / 接受人 / 理由 / 补丁计划；**报告首段必须显式标注与「致命 / 严重未闭环即不可发布」硬规则的冲突与接受人**）；对应缺陷状态改为 `已接受`；交付 |

## 修复循环（a → b → c）

- **a** 按触发原因分派（只派 engineer 修不了覆盖缺口）：
  - 缺陷类（51 未闭环缺陷 / 60 未闭环审查问题）→ 调度 engineer：输入 `docs/51-defects.md`（或 `docs/60-review.md` 问题清单）+ `docs/50-testcases.md`（关联 TC 复现步骤）+ 相关上游契约 + `docs/40-changelog.md` → 修复并追加 CHG 记录；
  - 覆盖不达标 / 用例缺口类 → 调度 test-designer 补 `docs/50-testcases.md` 用例（或 test-executor 补执行并回写 50 结果）。
- **b** 重新调度 test-executor 回归：输入 `docs/51-defects.md` 待回归缺陷与当前状态 + `docs/40-changelog.md` 本次修复改动 + 相关上游契约 → 更新 `docs/50-testcases.md`（回写结果）、`docs/51-defects.md`（逐条更新状态）与 `docs/52-qa-report.md`。
- **c** 自动循环最多 2 轮；**出口与缺陷级别解耦**：第 2 轮后只要存在任何未消除的阻断项（未闭环致命 / 严重缺陷、覆盖不达标或其他阻断项、尚未经用户接受的一般缺陷），**一律停止并把残留项清单交用户决断**——不只认致命 / 严重，否则行 3 返工、行 4 覆盖缺口这类不含致命 / 严重的场景会在「重判 → 再进循环」之间静默空转。**按用户选择执行**（每次人工续跑后回到本决断点，直到用户明确选择「带残留接受」或「终止」为止——不会因行 0 自动无限循环）：
  - 「**继续修复**」→ 再跑一轮 a + b（此轮为人工触发，**不计入自动循环上限（最多 2 轮）**——该上限只约束由缺陷状态自动触发的循环；人工触发的重跑不受此限）；
  - 「**带残留接受**」→ 按上表行 5 执行；
  - 「**终止**」→ 立即停止流程，输出当前全部产物路径与未闭环缺陷清单，不再调度任何子代理。

## 结论字符串（唯一枚举）

```
可发布 ｜ 有条件发布 ｜ 有条件发布（含残留缺陷） ｜ 不可发布（待确认接受） ｜ 不可发布
```

> **test-executor 的边界**：test-executor 只能基于 F1/F2 给出**建议结论**（对应行 0–4 范围）；「有条件发布（含残留缺陷）」**不在其建议范围内**——该结论仅当主对话在调度指令中明确指示「带残留接受」后，由 test-executor 在重调度中落盘。最终结论一律由主对话按本表判定并在交付总结中签署。
