## 判据定义（判定顺序之前必读）

下表条件里的「**覆盖达标**」「**其他阻断项**」「**缺陷级别**」是本状态机的**输入**。三者在此**单点定义、闭集枚举**，任何角色不得各自解释——本表此前只在条件里引用它们、从未定义，结果是**同一份事实可以落到不同结论行**（如「98/98 已执行」这一句既被读作达标也被读作未达标、缺陷定级只能现场写散文论证）。

### D1　覆盖达标 / 覆盖不达标

**覆盖达标 = 下列三条同时成立**：

1. **需求覆盖完整**：`docs/10-prd.md` 的每条 AC 至少被 `docs/50-testcases.md` 的一条 TC 关联（关联关系由 test-designer 在 50 中显式声明，主对话抽查）。
2. **执行覆盖闭合**：分母 = 50 **当前版本的全部 TC 编号**（含标注「手动」者）；分子 = 本轮**已执行且给出明确结论**（通过 / 失败）的 TC。存在未执行 / 无法执行 / 结论不明确者 → **不达标**（手动用例同样计入分母，必须有执行记录：执行人、时间、结论）。
3. **无静默缩表**：任何使分母变小的动作（删用例、合并用例、降级为「不作要求」）必须经契约裁决并留下**编号级**记录；禁止以「这条没法测」为由把 TC 移出分母——否则分母可被改小来凑达标。

- **「不可执行」不豁免登记**：无法执行的 TC 一律按 `docs/artifacts.md` §3.1 登记为 OBS（含责任人 + 计划执行时点），**其存在本身即判覆盖不达标**，除非经 `F6` 显式接受（→ 行 3.5）。
- **覆盖达标 ≠ 质量达标**：前者只回答「该测的是否都测了」；通过与否由缺陷台账与级别决定。两者不可互相替代、不可互相放行。

### D2　其他阻断项（行 4 用）

除「未闭环致命 / 严重」（由行 0 单独拦截）与「覆盖不达标」外，下列**被显式登记**的项构成阻断：

1. 未处置的「**契约冲突上报**」或未消解的「**待确认清单**」项；
2. 被**显式标注为「阻断」的 OBS**（环境 / 证据 / 工具链类）——`52:OBS-nn` 由 test-executor 标注、`60:OBS-nn` 由 code-reviewer 标注，**逐条标注「阻断 / 非阻断」**。**标注必须是可机械提取的结构化字段，不得只写「不再构成任何阻断」「不作为阻断项」这类散文式否定**——否则本项无法判定，本行整条落空（实测：52 的 OBS-10 / OBS-11 即是此形）；**漏标注者按「阻断」处理**（推定阻断，逼登记方表态）；
3. 上游契约为「**待复核**」状态、失效传播矩阵要求的复核未完成（`docs/artifacts.md` §5：不重跑不能进入下一阶段）；
4. `docs/60-review.md` 中状态为 `未闭环` 的 `REV-xx` 审查问题（致命 / 严重级已由 `/feature` 第 5 步单独拦截并给出接受路径，此处不再重复；**一般 / 建议级 REV 此前不在任何判定行的条件里**，修复循环 a 却把「60 未闭环审查问题」列为 engineer 的派活触发条件 —— 那是一个没有任何判定行能产生的进入条件，现由本项补齐）。

### D3　缺陷级别（F1 与各行判定用）

级别由**基准档 + 降级规则**唯一确定，不由各角色凭语感给出：

| 基准档 | 判据（按 ① 判定） | 本仓定级实例（校准用，均为已签署产物中的历史定级） |
| --- | --- | --- |
| **致命** | 业务终态被破坏且不可恢复（数据 / 资金 / 库存 / 权限终态错误） | （本仓无实例） |
| **严重** | 业务终态错误或产生多余副作用；或安全边界可被绕过 | （本仓无实例） |
| **一般** | **业务终态正确**（冲突被识别、事务整体回滚、可自行恢复），但有**功能偏差**：机制层面失效、对外语义偏差（错误码分层、契约状态码）、用户可见行为错误 | BUG-01（HTTP 码与契约不符，未产生第二次副作用）、BUG-05（重试链对后半段写入点失效，但整体回滚、可自行重试恢复） |
| **建议** | 业务终态正确且不变量全满足，且**无功能偏差**：可维护性 / 一致性 / 文案 / 序列化格式 / 门禁类问题 | BUG-02（时区标识）、BUG-03 与 REV-21（文案与冻结面不一致）、REV-20（格式门禁） |

- **降级只允许一档，且限于展示层**：仅当偏差**限于展示层**（文案 / 名称 / 格式）、**触发窗口极小**（竞态 / 特定时序）、且业务终态与不变量全满足时，可降一档——BUG-04（竞态下弹层奖品名为空、中奖记录本身正确）即按此由「一般」降为「建议」。
- **不得降级的两类**：① 触及**数据完整性与安全边界**的，直接按致命判；② **机制层面失效 / 对外语义偏差**（重试链失效、错误码分层被绕过、契约状态码不符）不适用降级——它们说明的是结构性缺陷，不是"偶尔才遇到"。
- **每条缺陷 / 审查问题必须写明定级依据**：对应上述判据的**实测事实**（终态如何、数据是否受损、触发条件、影响面），不得只写级别。
- 对定级有异议走 `docs/51-defects.md` §6「定级异议登记」，由主对话裁决。
- **本表用于今后的定级**；已签署产物中的历史定级不回改（见 `docs/development-spec.md` 13.4：历史记录不回改）。
