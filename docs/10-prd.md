## 1. 背景与目标

### 1.1 业务背景

- 原始需求（见 `docs/00-brief.md` 第 1 节）：做一个「转盘抽奖功能」，采用前后端分离。
- 该需求在本仓库同时承担**全链验证**职责：用户要完整跑通七角色研发流水线（product-manager → prototype-designer → software-architect → engineer → code-reviewer → test-designer / test-executor）。因此本期范围刻意收敛为**单次迭代可端到端交付**的完整闭环——注册/登录 → 抽奖 → 中奖记录，不引入真实履约、支付、风控中台等重型依赖。
- 原始需求未给出任何业务约束（奖池内容、概率模型、次数限制、用户体系、是否真实发放等）；本文采用的全部默认假设集中登记在附录 B，**已于 2026-09-17 经用户评审门确认定稿**，构成下游基线；后续如需变更，按 `docs/artifacts.md` 失效传播矩阵复核下游。

### 1.2 产品目标（可量化）

| 编号 | 目标 | 度量 |
| --- | --- | --- |
| G1 | 主链路闭环：新用户可完成 注册 → 登录 → 抽奖（中奖 / 未中奖两条路径）→ 查看中奖记录 | E2E 用例通过率 100%（无阻塞缺陷） |
| G2 | 规则正确性：次数限制、幂等、库存扣减在并发下不失控 | 并发用例 0 超发、0 重复扣次；跨日重置判定准确率 100% |
| G3 | 概率可验证：加权随机分布符合配置权重 | 固定随机源下抽样 ≥ 10000 次，各条目频率偏差 ≤ 2 个百分点 |
| G4 | 性能：抽奖判定接口响应达标 | 抽奖接口 P95 ≤ 500ms、记录列表 ≤ 300ms（测试环境单机基准） |
| G5 | 流程验证：七角色产物齐全、评审门通过 | `docs/artifacts.md` 登记的产物 00/10/20/30/40/50/51/52/60 全部产出 |

### 1.3 非目标（本期明确不做）

真实奖品发放与核销、支付 / 物流、后台奖品管理端与 RBAC、风控反作弊、排行榜与运营报表、多语言与多地区、抽奖历史（含未中奖）查询。完整清单见第 6 章 Won't。

## 2. 用户与场景

### 2.1 目标用户

| 用户 | 描述 | 本期诉求 |
| --- | --- | --- |
| C 端参与者 | 拥有账号的普通用户 | 登录后参与转盘抽奖，查看剩余次数与本人中奖记录 |
| 运营人员 | 维护奖池内容的角色 | 本期无操作界面；奖池由初始化数据承载（默认配置见 FR-03），管理能力列入 v2 |

### 2.2 核心场景

| 编号 | 场景 |
| --- | --- |
| S1 | 新用户参与：注册 → 登录 → 打开抽奖页（转盘 + 今日剩余 3 次）→ 点击抽奖 → 动画停下 → 结果反馈 |
| S2 | 中奖：抽出有库存奖品 → 展示奖品名 → 次数 -1、库存 -1、中奖记录 +1 |
| S3 | 未中奖：抽出「谢谢参与」→ 弹层提示 → 次数 -1、无记录 |
| S4 | 次数用尽：第 4 次点击被拒 → 按钮禁用 + 引导「明日 0 点重置」 |
| S5 | 查询记录：进入「我的中奖记录」→ 分页列表（仅本人） |
| S6 | 跨日回归：次日 0 点后重新获得 3 次机会 |
| S7 | 库存耗尽：某奖品抽完即不再中出，其余条目按剩余权重归一 |
| S8 | 异常网络：请求超时后重试，由幂等键保证不重复扣次 |

## 3. 功能需求

### 3.1 用户与登录

#### FR-01 用户注册

- **功能描述**：访客通过「用户名 + 密码」注册账号，用户名全局唯一。
- **交互细节**：表单含 用户名、密码、确认密码；校验失败就地展示错误、提交中禁用按钮；注册成功后自动登录并跳转抽奖页。
- **业务规则**：
  1. 用户名 4–20 位，仅字母 / 数字 / 下划线，全局唯一且**不区分大小写**（`Admin` 与 `admin` 视为冲突）；冲突时提示「用户名已被占用」。
  2. 密码 8–20 位，须同时包含大写字母、小写字母与数字（依据 CR-01，按 `docs/development-spec.md` 8.1 口径）；确认密码必须一致。
  3. 密码加密存储（BCrypt，规范既定）；任何日志、响应不得出现明文密码。
  4. 注册成功即签发登录凭证（JWT 双 token，机制遵循仓库规范），进入抽奖页。

#### FR-02 用户登录与登出

- **功能描述**：已注册用户凭用户名 + 密码登录；会话期内保持登录态；支持登出；未登录不可触达抽奖与记录。
- **交互细节**：登录失败统一提示「用户名或密码错误」（不区分具体原因，防账号枚举）；登录成功默认进入抽奖页（有回跳目标则回跳原页）；登出后回到登录页。
- **业务规则**：
  1. 凭证签发与 401 无感刷新遵循仓库规范既有机制，本 PRD 不重复定义实现。
  2. 登录接口必须配置限流（规范既定）。
  3. 未登录访问抽奖页：前端路由守卫重定向登录页；直接调用受保护接口：后端返回 401。
  4. 凭证失效且刷新失败时按 FR-10 引导重新登录。

### 3.2 抽奖页与奖池

#### FR-03 奖池与转盘展示

- **功能描述**：抽奖页转盘扇区以后端奖池为准渲染，扇区与奖池条目一一对应（含「谢谢参与」）。
- **交互细节**：进入页面自动拉取奖池；加载中显示占位；失败可重试；奖品库存为 0 时仍保留扇区展示（不改变转盘形态），但不可中出（见 FR-05-R3）。
- **业务规则**：
  1. **权重与库存不得返回给前端**（防探测）；前端不参与概率计算、不预设落点。
  2. 通过「启用开关」控制奖品上下架；不做删除（历史记录需可追溯）。
  3. 默认奖池（默认假设，见 Q1）：

| 序号 | 名称 | 类型 | 权重 | 库存 |
| --- | --- | --- | --- | --- |
| 1 | 一等奖 · 机械键盘 | 实物 | 1 | 3 |
| 2 | 二等奖 · 蓝牙耳机 | 实物 | 3 | 10 |
| 3 | 三等奖 · 定制马克杯 | 实物 | 10 | 50 |
| 4 | 幸运奖 · 平台优惠券 | 虚拟 | 20 | 200 |
| 5 | 谢谢参与 | 未中奖 | 66 | 不限 |

#### FR-04 剩余抽奖次数展示

- **功能描述**：抽奖页展示「今日剩余次数」（默认每人每日 3 次）。
- **交互细节**：初始显示 3 次；每次抽奖完成后立即刷新；次数为 0 时抽奖按钮禁用并显示「今日抽奖次数已用完，明日 0 点重置」。
- **业务规则**：剩余次数 = 每日上限（默认 3） − 当日已消耗；**未中奖同样消耗次数**（Q3）；最终判定以后端为准，前端展示仅为体验。

### 3.3 抽奖核心

#### FR-05 执行抽奖

- **功能描述**：用户点击「抽奖」，由**后端**完成资格校验、加权随机判定、次数与库存扣减，并返回结果。
- **交互细节**：点击后按钮立即禁用（防连点），等待后端响应；响应成功才播放动画（FR-06）；失败不播放动画并按 FR-10 提示；重试沿用同一幂等键。
- **业务规则**（编号 R1–R10 供下游稳定引用）：
  - **R1 结果来源**：请求不携带任何影响结果的业务参数（幂等键除外）；结果只能由后端判定，前端无权指定。
  - **R2 校验顺序**：登录凭证 → 幂等键（重复请求重放首次结果，不重复消耗）→ 剩余次数 > 0 → 抽取。
  - **R3 候选集**：启用中条目 ∩（「谢谢参与」或 库存 > 0）；候选集为空时返回业务错误「奖品已抽完，请稍后再来」（默认奖池含常驻「谢谢参与」，正常不触发）。
  - **R4 抽取算法**：加权随机，P(i) = wᵢ / Σ(候选集权重)。
  - **R5 中奖（非谢谢参与）**：次数 -1、库存 -1、写中奖记录，三者同一事务内完成；库存不允许扣成负数。
  - **R6 未中奖（谢谢参与）**：仅扣次数，不写记录。
  - **R7 时间口径**：「今日」以服务端时间（UTC+8 自然日）判定，不信任客户端时间。
  - **R8 审计**：每次抽奖写审计日志（用户、时间、结果条目、消耗次数），不记录密码 / token。
  - **R9 可测试性**：测试环境可将随机源 / 权重配置为确定性结果（用于 E2E 验证中奖与未中奖两条链路）；该能力仅测试环境可用，生产环境必须不可达。
  - **R10 返回内容**：结果条目标识（供前端扇区定位）+ 最新剩余次数。

#### FR-06 抽奖动画与结果反馈

- **功能描述**：前端在收到后端结果后播放转盘动画，最终落点与后端返回条目**严格一致**；动画结束后展示结果。
- **交互细节**：转盘旋转 ≥ 2 圈后减速停稳在结果扇区 → 弹层展示：
  - 中奖：「恭喜获得 {奖品名称}」+「已记入我的中奖记录」；
  - 未中奖：「谢谢参与，再接再厉」。
- **业务规则**：
  1. 动画期间禁止再次点击 / 重复提交；动画仅为表现层，不参与任何判定。
  2. 后端返回失败时不播放动画（立即复位），按 FR-10 提示。
  3. 页面刷新后状态与后端一致（次数、记录）。

#### FR-07 每日次数限制与重置

- **功能描述**：每人每日上限 3 次；按 UTC+8 自然日 00:00 重置。
- **业务规则**：
  1. 重置由服务端判定（FR-05-R7）；跨日后历史消耗不影响新一天。
  2. 客户端在每次进入页面与每次抽奖后与服务端同步剩余次数。

#### FR-08 并发与一致性保障

- **功能描述**：同一用户在并发 / 重试场景下不得突破次数与库存约束。
- **业务规则**：
  1. 同一用户并发抽奖：超出剩余次数的请求必须被拒绝（数据库唯一约束兜底）。
  2. 同一奖品并发扣减：库存不得为负、不得超发。
  3. 事务失败整体回滚，次数、库存、记录三方一致。
  4. 幂等：同一 `Idempotency-Key` 的重复提交（含并发同时提交）返回与首次一致的结果；缺少或更换 key 视为新请求，正常消耗次数。

### 3.4 记录

#### FR-09 我的中奖记录

- **功能描述**：登录用户分页查询本人中奖记录（不含未中奖）。
- **交互细节**：列表展示 奖品名称、中奖时间；默认按中奖时间倒序；每页 10 条；空态「还没有中奖记录，去试试手气吧」；加载失败可重试。
- **业务规则**：
  1. 接口恒定返回当前登录用户的数据，**不接受 userId 参数**（天然隔离越权）。
  2. 记录只读：不提供修改 / 删除入口。
  3. 时间存储遵循 ISO 8601，展示格式 `yyyy-MM-dd HH:mm`。

### 3.5 通用

#### FR-10 异常与错误提示

- **功能描述**：统一处理登录失效、业务拒绝、系统异常三类反馈，前端不得白屏。
- **业务规则**：
  1. 401（无感刷新失败）：引导重新登录，登录后回跳原目标页。
  2. 业务拒绝（错误码 ≥ 1000）：直接展示后端文案（如「今日抽奖次数已用完」「奖品已抽完」「请勿重复提交」）。**新增业务错误码由 engineer 按 `docs/error-codes.md` 取号登记，本 PRD 不预设号码。**
  3. 网络 / 系统异常：展示「系统繁忙，请稍后重试」并允许重试；重试沿用同一幂等键（FR-08-4）。
  4. 所有用户可见文案集中管理，为后续 i18n 外置预留（见 4.5）。

#### FR-11 奖池数据初始化

- **功能描述**：系统首次初始化时写入默认奖池（FR-03 表）；本期不做管理界面（MVP 边界，见第 6 章）。
- **业务规则**：
  1. 初始化随数据库迁移 / 种子脚本执行，可重复执行且不产生重复条目。
  2. 测试环境允许通过配置覆盖权重与库存（供 AC-14 / AC-16 构造确定性场景）；生产环境使用默认配置。

## 4. 非功能需求

### 4.1 性能

- 抽奖判定接口 P95 ≤ 500ms；我的中奖记录查询 ≤ 300ms（测试环境单机基准）。
- 前端路由懒加载；记录列表强制分页，禁止全量查询。

### 4.2 安全

- 抽奖、记录相关接口全部鉴权，未登录返回 401。
- 抽奖结果不可由客户端影响；权重、库存不向前端暴露（FR-05-R1、FR-03-1）。
- 中奖记录恒定返回本人数据，不提供越权入口（FR-09-1）。
- 密码 BCrypt 存储；日志禁止输出密码 / token / 密钥（规范红线）。
- 登录接口限流（规范既定）；抽奖接口按用户维度限流（建议 ≤ 10 次 / 分钟，Should）。
- 前端防连点与按钮隐藏仅为体验优化，服务端逐次校验（规范红线）。

### 4.3 数据一致性

- 次数、库存、中奖记录在同一事务内变更；并发下不得超发、超扣（FR-08）。
- 抽奖记录不可修改 / 删除；用户、奖品、记录不做物理删除（遵循规范逻辑删除约定）。
- 关键操作审计：每次抽奖留痕（FR-05-R8）。

### 4.4 兼容性

- 桌面：Chrome / Edge 最新两个大版本；移动端：常见浏览器（Safari / Chrome / 微信内置）375–428px 宽度可用。
- 不承诺 IE 及更老版本浏览器。

### 4.5 i18n 检查项（判定：本期不适用，做预留）

- 本期为**单语言（简体中文）、单地区（UTC+8）**，不做多语言切换，故 i18n 不列为验收项；但完成以下检查：
  1. 文案：用户可见文案集中管理，不散落在组件内，为后续外置预留。
  2. 时间：存储与接口一律 ISO 8601；展示按 UTC+8；「今日」判定用服务端时区（FR-05-R7）。
  3. 货币：本期奖品不含金额字段，无货币格式化需求（后续如加入面额奖品再引入）。
- 若 Q10 确认需要多语言 / 多地区，本项升级为 Must：引入文案外置与日期 / 货币格式化方案，工作量相应增加。

### 4.6 可测试性

- 抽奖随机源可被测试替换（确定性），测试环境可固定权重与结果（FR-05-R9）。
- 「今日」判定依赖可注入时钟，支撑跨日用例（AC-11）。
- 上述开关仅测试环境可用，生产环境不可达。

### 4.7 仓库规范约束（引用，不重复技术选型）

- 前后端分离；接口 URL `/api/v1/[controller]`（小写）；统一响应 `ApiResult<T>`，`code=0` 成功。
- 分页参数 `pageIndex` 从 1 起、`pageSize` 上限 100；时间 ISO 8601；提交 `application/json`。
- 抽奖等提交类接口携带 `Idempotency-Key`（规范 6.5）。
- 新增业务错误码（≥1000）先查 `docs/error-codes.md` 取号登记，禁止编造。
- 技术选型（框架、分层、表结构、缓存策略）由 `docs/30-architecture.md` 决定，本文不涉及。

## 5. 验收标准（Given / When / Then）

**AC-01（关联 FR-01）注册成功**
- Given 访客在注册页且用户名未被占用
- When 提交合法用户名与密码（8–20 位且同时含大写字母、小写字母与数字，两次一致）
- Then 注册成功并自动登录进入抽奖页，显示「今日剩余 3 次」

**AC-02（关联 FR-01）注册校验拦截**
- Given 访客在注册页
- When 依次提交与已有账号重复（含大小写变体）的用户名、不满足强度的密码（如缺少大写字母）、两次不一致的密码
- Then 均阻止提交并就地提示对应错误（用户名已被占用 / 密码需 8–20 位且同时含大写字母、小写字母与数字 / 两次输入不一致），不创建账号

**AC-03（关联 FR-02）登录成功**
- Given 已注册用户
- When 输入正确凭证并登录
- Then 登录成功进入抽奖页（若由受保护页跳转而来则回跳原页）

**AC-04（关联 FR-02）登录失败**
- Given 用户输入错误的用户名或密码
- When 提交登录
- Then 提示统一文案「用户名或密码错误」，不出现区分性提示（防账号枚举），不签发凭证

**AC-05（关联 FR-02、FR-10）未登录拦截**
- Given 未登录（或凭证失效且刷新失败）
- When 访问抽奖页或调用抽奖 / 记录接口
- Then 前端重定向或引导登录、后端返回 401；登录成功后回到原目标页

**AC-06（关联 FR-03）奖池展示一致**
- Given 已登录用户
- When 打开抽奖页
- Then 转盘扇区与后端启用中的奖池条目一一对应（默认 5 条），且接口响应中不包含权重与库存字段

**AC-07（关联 FR-04）剩余次数展示**
- Given 已登录用户当日尚未抽奖
- When 打开抽奖页并完成一次抽奖（中奖或未中奖）
- Then 抽奖前显示剩余 3 次，抽奖后刷新为 2 次

**AC-08（关联 FR-05、FR-06）中奖路径**
- Given 测试环境将某库存 > 0 的奖品配置为必然中出
- When 用户点击抽奖并等待动画结束
- Then 转盘落点与该奖品扇区一致；弹层显示奖品名；次数 -1、该奖品库存 -1、我的中奖记录新增 1 条（奖品名与时间正确）

**AC-09（关联 FR-05、FR-06）未中奖路径**
- Given 测试环境配置为必然抽出「谢谢参与」
- When 用户点击抽奖并等待动画结束
- Then 转盘停在「谢谢参与」扇区；弹层提示未中奖；次数 -1；中奖记录不新增

**AC-10（关联 FR-07）次数用尽**
- Given 用户当日已消耗 3 次
- When 尝试第 4 次抽奖（含绕过前端直接调接口）
- Then 前端按钮禁用并提示「今日抽奖次数已用完，明日 0 点重置」；后端返回业务错误码拒绝，次数与库存均不变

**AC-11（关联 FR-07）跨日重置**
- Given 用户当日次数已用尽（服务端时钟可控）
- When 将服务端时间推进到次日 00:00 之后
- Then 剩余次数恢复为 3、可再次抽奖，前一日记录不受影响

**AC-12（关联 FR-08）幂等**
- Given 用户有剩余次数
- When 使用同一 `Idempotency-Key` 重复提交抽奖（含并发同时提交）
- Then 仅第一次生效（次数仅扣 1、中奖记录至多 1 条），后续请求返回与首次一致的结果

**AC-13（关联 FR-08）并发防超发**
- Given 某奖品库存 = 1 且被配置为必然中出（测试环境），两个不同用户均有剩余次数
- When 两个请求并发抽奖
- Then 仅 1 个请求中得该奖品，库存扣至 0 且不为负；另一请求按剩余候选集返回结果，次数正常扣减 1 次

**AC-14（关联 FR-05）库存耗尽剔除**
- Given 某奖品库存置 0（测试环境配置）
- When 通过服务级测试连续抽取 ≥ 1000 次
- Then 该奖品出现 0 次；其余候选按剩余权重归一，频率与归一权重偏差 ≤ 2 个百分点

**AC-15（关联 FR-09）中奖记录与隔离**
- Given 用户 A 有 2 条中奖记录、用户 B 有 1 条
- When 用户 A 查询我的中奖记录并翻页
- Then 仅返回 A 的记录，按中奖时间倒序分页（默认 10 条 / 页）；接口不接受 userId 参数，A 无法获取 B 的记录

**AC-16（关联 FR-05）权重分布**
- Given 默认奖池与固定随机源
- When 抽样 ≥ 10000 次
- Then 各条目出现频率与理论权重偏差 ≤ 2 个百分点

**AC-17（关联 FR-10）异常反馈与重试**
- Given 抽奖请求因网络超时未返回
- When 用户重试（沿用同一幂等键）且最终仍失败
- Then 不重复扣次，展示「系统繁忙，请稍后重试」，页面无白屏

**AC-18（关联 FR-11）奖池初始化**
- Given 全新数据库
- When 系统初始化完成后查询奖池
- Then 返回与 FR-03 默认配置一致的 5 条条目；初始化脚本重复执行不产生重复条目

## 6. 优先级（MoSCoW）与 MVP 范围

| 优先级 | 范围 |
| --- | --- |
| Must | FR-01 注册、FR-02 登录与登出、FR-03 奖池与转盘展示、FR-04 剩余次数展示、FR-05 执行抽奖、FR-06 动画与结果反馈、FR-07 每日次数限制与重置、FR-08 并发与一致性、FR-09 我的中奖记录、FR-10 异常与错误提示、FR-11 奖池初始化 |
| Should | S1 记录列表空态 / 加载态 / 失败重试交互（FR-09）；S2 次数用尽文案含精确重置时间引导（FR-04）；S3 抽奖接口按用户限流（4.2） |
| Could | C1 中奖动效增强（彩带 / 音效）；C2 抽奖结果分享图（不落地社交传播功能） |
| Won't（本期不做，v2 候选） | W1 后台奖品管理端与 RBAC；W2 真实奖品履约（核销 / 支付 / 物流）；W3 风控反作弊（设备指纹、多账号识别）；W4 排行榜 / 运营报表 / 裂变传播；W5 多语言与多地区（i18n）；W6 抽奖历史（含未中奖）查询 |

**MVP 范围**：Must 全量（FR-01–FR-11）构成验收基线，即「注册/登录 → 抽奖（中奖/未中奖）→ 中奖记录」的完整闭环。Should 三项成本低、默认纳入本期交付；若工期紧张由主对话裁决裁剪，不影响 AC 基线。Could / Won't 不进入本期验收与测试范围。

**后台奖品管理页结论：Won't**。理由：① 管理端会引入 RBAC、管理端路由与另一套页面体系，与「单次迭代端到端可交付」的验证目标不匹配；② 奖池由初始化数据承载即可满足用户侧全链路验证，用户侧列表分页（FR-09）已覆盖表格类交互的验证点；③ 管理端列入 v2 候选（W1），本期奖池变更通过配置与迁移完成。

## 附录 A：术语与约定

> 经检索，本仓库不存在抽奖相关既有术语 / 约定（亦无应用代码），本节为首次定义，下游产物必须沿用。ID 体系遵循 `docs/artifacts.md` 第 3 节（FR / AC / MOD / API / TC…）。

| 术语 | 建议命名 | 定义 |
| --- | --- | --- |
| 抽奖 | draw / lottery | 用户消耗 1 次机会并获得后端判定结果的一次行为 |
| 奖池 | prize pool | 全部可抽取条目的集合 |
| 奖品条目 | prize item | 奖池中一条可中出项：名称、类型、权重、库存、启用状态 |
| 谢谢参与 | no-prize | 常驻的未中奖条目，不占库存、不写中奖记录 |
| 权重 | weight | 抽取用的相对概率值（非百分比，内部按候选集归一） |
| 候选集 | candidate set | 参与本次抽取的条目子集（FR-05-R3） |
| 每日次数 | daily quota | 每人每自然日（UTC+8）可抽奖次数，默认 3 |
| 剩余次数 | remaining attempts | 每日次数 − 当日已消耗 |
| 中奖记录 | winning record | 用户中得奖品后生成的记录，仅含中奖项，不含未中奖 |
| 幂等键 | Idempotency-Key | 防重复提交请求头（UUID），沿用规范 6.5 |
| 自然日 | calendar day | UTC+8 时区 00:00–23:59 的一天 |

接口路径、模块编号与数据表命名由 `docs/30-architecture.md` 定义，须遵守 `/api/v1/[controller]` 小写与 `ApiResult<T>` 约定（4.7）。
