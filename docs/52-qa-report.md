#### （一）执行方式说明（注入手法与前置条件，须与结论一同阅读）

- **TC-56b 注入手法 = InnoDB 父行锁阻塞子表 FK 检查**：在**另一条连接**上 `START TRANSACTION; SELECT Id FROM User WHERE Id=<uid> FOR UPDATE; SELECT SLEEP(300) AS tc56b_lock_holder;`（保持不提交）。抽奖事务走到第 ⑥ 步 `WinningRecord` INSERT 时，FK 检查须对 `User` 父行加 S 锁 → 被阻塞 → 失败。**FK 事实经本角色 `SHOW CREATE TABLE` 实测复核**（未采信转述）：`DrawRequest` / `UserDrawQuota` / `AuditLog` **无任何 FK**；`WinningRecord` **有** `FK_WinningRecord_User_UserId` 与 `FK_WinningRecord_PrizeItem_PrizeItemId`。故 ① 幂等行 / ② 扣次 / ③ 扣库存**均不在阻塞路径**，唯一可阻塞点即 ⑥。
