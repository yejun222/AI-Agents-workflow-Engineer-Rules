# 全局开发规范（用户级 · 技术栈无关）

> 用途：复制到 `~/.claude/CLAUDE.md`（Windows：`C:\Users\<用户名>\.claude\CLAUDE.md`），对本机**所有项目、所有会话**生效。
> 与项目内 CLAUDE.md 的关系：项目文件更具体，冲突时以**项目文件**为准；本文件兜底。

## 本文件的边界（改之前先读）

**只放「与具体技术栈无关」的条款。** 技术栈相关的规则（Vue / .NET / EF Core / shadcn / Tailwind 等）一律下沉到**各项目自己的** `CLAUDE.md` 与全量规范。

两条理由，都是实测出来的：

1. **错配**：本文件对**本机所有项目**生效，可能包含 Python / Go / 别的前端栈。写死某套技术栈的规则，对其它项目要么无用、要么误导。
2. **必然漂移**：本文件**无法引用**任何项目的规范文件（别的项目没有那些文件），因此它只能是**第三份手抄副本**。而「同一事实存在第二落点、两者之间没有护栏绑定」在本仓库实测中**必然分叉**——曾出现全局副本落后项目规范 7 条规则、且**从未被安装**（死文件）的情形。

> 下方的「工作准则」与「通用红线」与项目级规范的**通用部分**存在天然重叠——这是**兜底文件的固有代价**（兜底就是要复述默认值），不必消除，但要**保持最小**：只保留任何技术栈都成立、且极少变化的条款。

## 工作准则

1. **先确认再动手**：引入新第三方依赖、架构选型 / 目录结构变更、删除或重写已有文件、数据库表结构变更、破坏性接口变更、对外数据结构变更——必须先征得同意。
2. **复用优先**：先找项目里已有的封装与工具函数，不重复造轮子。
3. **完整可运行**：交付前用**项目自己的**构建 / 测试 / 格式命令验证，**不静默跳过失败项**；命令跑不通先排查环境原因并**如实反馈**，不要绕过。
4. **测试随行**：新增或修改逻辑必须附带测试，**本地跑通**才算完成。
5. **最小改动**：不做需求之外的"顺手重构"；发现越界问题**披露上报**，不擅自改。

## 通用红线（任何技术栈都成立）

- **禁止明文口令**：一律强哈希存储，禁止明文存储与传输。
- **敏感信息不入库入仓**：密钥 / 连接串 / 凭据走环境变量或密钥管理，禁止硬编码、禁止提交。
- **禁止字符串拼接 SQL**：一律参数化查询。
- **日志禁止输出口令、Token、密钥。**
- **外部输入必须校验；渲染服务端 / 用户输入必须转义或净化**，不直接注入 DOM。
- **跨域来源白名单显式配置**，禁止放开任意来源。
- **敏感字段脱敏后再返回**给前端，不依赖前端遮罩。
- **不可逆操作先确认**：删除文件、force push、发布制品、改数据库结构。
- **不可信结论要留痕**：如实记录"未执行 / 未验证 / 仅旁证"的项，不把缺失当成通过。

## 验证命令

**以项目内 `CLAUDE.md` 的命令为准。** 项目没有时，按该项目自身的技术栈选择构建 / 测试 / 格式命令——**不要套用本文件的假设**（本文件不声明任何技术栈）。
